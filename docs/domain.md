# 领域约定

描述织物属性、污渍、洗剂、设备和护理规则之间的适配事件。

聚合对象包括`garment_profile`、`care_rule`、`treatment_plan`、`processing_batch`。事件类型包括`GARMENT_ASSESSED`、`RULE_VERSIONED`、`PLAN_APPROVED`、`BATCH_STARTED`、`OUTCOME_REVIEWED`。所有发生时间都必须携带时区，版本号从 1 开始递增，基础校验不会改写调用方输入。

## 事件载荷

- `GARMENT_ASSESSED`：载荷还需包含 `material_evidence`, `stain_observations`。
- `PLAN_APPROVED`：载荷还需包含 `rule_version`, `risk_level`。
- `BATCH_STARTED`：载荷还需包含 `equipment_ref`, `formula_lot`。

相同事件标识的业务幂等、冲突隔离和状态推进由上层服务负责；本仓库只定义可稳定交换的基础事实。

## 运行时服务语义

`src/fabric_care/service.py` 在契约之上提供判定与调度服务，状态快照落盘，服务重启后期限继续生效。

### 判定

- 推荐温度取护理标签、设备能力、染色限制、辅料限制与污渍规则的最小约束；蛋白类污渍上限 40°C 以防固化，不按“温度越高清洁越强”排序。
- 日常去污与专业消毒分别成案；消毒须同时具备有效许可、设备能力与温度或化学许可路径，否则拒绝并回退为日常去污。
- 材质缺失或置信度不足时不臆测材质，输出保守方案（低温轻柔）与待确认项。
- 配方批次超出有效期或酶活性不足时拒绝酶预处理，并提示更换有效批次。

### 权限

- 配方供应方无权改写衣物标签。
- 高风险例外须由工艺主管批准；录入观察的门店人员不能独自批准。

### 发布与更正

- 方案发布时冻结所采用的规则版本与配方批次。
- 标签更正只取代未开始处理的方案；已开始或已完成的订单保留原依据并生成复查义务。

### 幂等与隔离

- 重复扫描返回原回执，不重复扣减洗剂或启动设备。
- 订单号相同而衣物、温度或配方批次不同的扫描进入隔离，不并入已有批次。
- 设备窗口分配在锁内完成，并发批次原子排程，冲突时顺延到当日下一个空档。

### 可解释性

- `explain_plan` 给出推荐温度依据、步骤、被拒绝处理的原因与待确认项。
- `responsibility_chain` 在结果偏离预期时给出从观察、判定、批准、发布、供应、执行到结果记录的责任链。
